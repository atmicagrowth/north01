# NORTH / 01

An online-only DTC premium apparel storefront. Next.js 16 with Payload CMS 3 embedded in the
same deployable, Postgres (Neon) as the source of truth, Stripe as the payment authority.

## Read before changing anything

This repository is the implementation of a written specification. Do not infer requirements
from the code alone.

**Precedence, highest first:**

1. `NORTH01_Implementation_Notes_and_Deviations.md` — what was actually decided and why. Overrides
   every document below it. **Append it at the end of every phase; a phase that changed behaviour
   without updating it is not finished.**
2. `NORTH01_Claude_Implementation_Plan_Current_OnlineOnly.md` — build order, architecture, phase gates.
3. `01_NORTH01_Tech_Stack_Current_OnlineOnly.md` — the only approved technology list.
4. `02_NORTH01_Features_and_Tech_Implementation_Current_OnlineOnly.md` — feature → technology map.
5. `03_NORTH01_Website_Structure_and_User_Flow_Current_OnlineOnly.md` — user-facing navigation and flow.

For anything visual, `NORTH01_Visual_Guide_OnlineOnly.md` is the source of truth and
`NORTH01_Visual_Reference_OnlineOnly.png` is directional context only.

Orientation for the codebase itself: `docs/ARCHITECTURE.md`, `docs/STACK_VERSIONS.md`,
`docs/DEVELOPMENT.md`.

## Rules that do not bend

- **Work in phase order.** Each phase has an acceptance gate. Do not build a later phase's
  feature early, and do not install its dependencies early.
- **The browser is never authoritative** — not for price, inventory, discount validity, tax,
  shipping, totals, permissions, or payment state. Recalculate server-side.
- **Only a signature-verified Stripe webhook marks an order paid.** Reaching the success page is not payment.
- **Online-only.** No store locator, hours, POS, BOPIS, curbside pickup, store-level inventory,
  or in-store returns. Inventory is centralized online fulfillment stock.
- **Never commit secrets.** `.env*` is git-ignored except `.env.example`.
- **Never build UI that looks functional but does nothing.**
- **Version pins are evidence-based.** `latest` is wrong for TypeScript and ESLint here — see
  `docs/STACK_VERSIONS.md` before upgrading anything.

## Verification

```
pnpm typecheck && pnpm lint && pnpm build
```

`pnpm lint` runs at `--max-warnings 0`. All three must pass before a phase is committed.
